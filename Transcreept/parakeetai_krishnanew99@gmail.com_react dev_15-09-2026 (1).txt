💬 **Question**: What are microtasks and macrotasks in JavaScript?

---

⭐️ **Answer**: In JavaScript, microtasks and macrotasks are two types of tasks in the event loop that manage asynchronous operations.

- **Macrotasks** (also called tasks) include events like setTimeout, setInterval, I/O operations, and UI rendering. They are queued in the macrotask queue.
- **Microtasks** include promises (then/catch/finally callbacks), MutationObserver callbacks, and queueMicrotask. They are queued in the microtask queue.

The event loop processes tasks in this order:
1. Executes one macrotask from the macrotask queue (e.g., a setTimeout callback).
2. Then runs all microtasks in the microtask queue until it is empty.
3. Then renders updates if needed.
4. Then repeats.

This means microtasks have higher priority and run immediately after the current macrotask completes, before the next macrotask starts. This helps with promise resolution and other quick asynchronous operations to happen promptly.

---

**Example:**

```javascript
console.log('script start');

setTimeout(() => {
  console.log('setTimeout macrotask');
}, 0);

Promise.resolve().then(() => {
  console.log('promise microtask');
});

console.log('script end');
```

Output order:
```
script start
script end
promise microtask
setTimeout macrotask
```

---

⭐️ **Summary**:
- Macrotasks: timers, I/O, UI events.
- Microtasks: promise callbacks, MutationObserver.
- Microtasks run immediately after the current macrotask before the next macrotask.
- This prioritization ensures smoother async behavior and UI responsiveness.

This understanding is crucial for optimizing React apps and handling async data flows effectively, as I have done in my projects using React and TanStack Query for intelligent API caching and rendering performance.

💬 **Question**: What are callbacks in JavaScript?

---

⭐️ **Answer**: Callbacks in JavaScript are functions passed as arguments to other functions that get executed after some operation completes, often asynchronously.

- They allow you to run code after an event or task finishes, such as after an API call, timer, or user interaction.
- Callbacks help manage asynchronous behavior by deferring execution until the result is ready.
- They can be synchronous or asynchronous, but are most commonly used for async operations.
- A callback function is invoked inside the outer function once the task is done.

---

**Example:**

```javascript
function fetchData(callback) {
  setTimeout(() => {
    const data = { id: 1, name: 'Sample' };
    callback(data); // invoke callback with data after delay
  }, 1000);
}

fetchData(function(result) {
  console.log('Data received:', result);
});
```

---

⭐️ **Additional context**:
- Callbacks were the primary way to handle async code before Promises and async/await.
- Improper use can lead to "callback hell," which is why Promises and async/await are preferred now.
- In my experience building React apps, I often use callbacks for event handlers and sometimes for legacy async code, but I prefer Promises and async/await for clearer, more maintainable code.

This understanding is foundational for frontend development and helps in managing asynchronous flows effectively.

💬 **Question**: What is lexical scoping in JavaScript?

---

⭐️ **Answer**: Lexical scoping in JavaScript means that the accessibility of variables is determined by their physical placement in the source code (the lexical context), and nested functions have access to variables declared in their outer scopes.

- The scope of a variable is fixed at the time of writing the code, not at runtime.
- Inner functions can access variables declared in their outer functions, but outer functions cannot access variables inside inner functions.
- This is why closures work in JavaScript — inner functions "remember" the environment in which they were created.

---

**Example:**

```javascript
function outer() {
  const outerVar = 'I am outside!';

  function inner() {
    console.log(outerVar); // inner function can access outerVar due to lexical scoping
  }

  inner();
}

outer(); // Logs: I am outside!
```

---

⭐️ **Additional context**:
- Lexical scoping is fundamental to understanding closures, module patterns, and variable lifetimes in JavaScript.
- It contrasts with dynamic scoping, where variable scope depends on the call stack at runtime.
- In my React projects, understanding lexical scoping helps me manage state and closures correctly, especially when using hooks like `useEffect` or event handlers that capture variables from their surrounding scope.

[11:43 AM] AI
💬 **Question**: What is the difference between shallow copy and deep copy in JavaScript?

---

⭐️ **Answer**: 

- A **shallow copy** creates a new object or array but only copies the references of nested objects or arrays. This means changes to nested objects in the copy will affect the original because they share the same references.
- A **deep copy** creates a completely independent clone of the original object or array, including all nested objects and arrays, so changes in the copy do not affect the original.

---

**Key differences:**

| Aspect           | Shallow Copy                                  | Deep Copy                                      |
|------------------|----------------------------------------------|------------------------------------------------|
| Copies           | Top-level properties only                      | All nested properties recursively               |
| Nested objects   | Shared references (not cloned)                 | Fully cloned (independent)                       |
| Use cases        | When nested objects don’t need to be independent | When full independence from original is needed |
| Methods          | `Object.assign()`, spread operator `{...obj}` | `JSON.parse(JSON.stringify(obj))`, libraries like lodash `_.cloneDeep()` |

---

**Example:**

```javascript
// Shallow copy example
const original = { a: 1, b: { c: 2 } };
const shallowCopy = { ...original };
shallowCopy.b.c = 42;
console.log(original.b.c); // 42 — nested object is shared

// Deep copy example
const deepCopy = JSON.parse(JSON.stringify(original));
deepCopy.b.c = 100;
console.log(original.b.c); // 42 — original is unaffected
```

---

⭐️ **Additional context**:  
In my React projects, I often use shallow copies for state updates when only top-level changes are needed, but for deeply nested state, I ensure deep copies to avoid unintended mutations. For complex objects, I prefer utility libraries like lodash’s `cloneDeep` for reliable deep cloning.

💬 **Question**: Can you explain what async is?

---

⭐️ **Answer**: In JavaScript, **async** refers to asynchronous programming, which allows code to run without blocking the main thread, enabling tasks like data fetching or timers to happen in the background while the rest of the code continues executing.

- The keyword `async` is used to declare an asynchronous function.
- An `async` function always returns a Promise.
- Inside an `async` function, you can use the `await` keyword to pause execution until a Promise resolves, making asynchronous code easier to write and read, almost like synchronous code.
- This helps manage operations that take time, such as API calls, file reading, or timers, without freezing the UI or blocking other JavaScript execution.

---

**Example:**

```javascript
async function fetchData() {
  try {
    const response = await fetch('https://api.example.com/data');
    const data = await response.json();
    console.log(data);
  } catch (error) {
    console.error('Error fetching data:', error);
  }
}

fetchData();
```

---

⭐️ **Additional context**:  
In my React projects, I use async functions combined with hooks like `useEffect` and libraries like TanStack Query to handle asynchronous data fetching efficiently, improving UI responsiveness and user experience. Understanding async/await is essential for managing asynchronous workflows cleanly in modern JavaScript and React development.

💬 **Question**: What will be the output of `obj.greet()` when `greet` is defined as an arrow function logging `this.name`?

---

⭐️ **Answer**: The output of `obj.greet()` will be `undefined`.

---

**🔑 Key Steps**:

- The object `obj` has a property `name` with value `"John"`.
- The `greet` method is defined as an arrow function: `() => { console.log(this.name); }`.
- Arrow functions do not have their own `this` context; they inherit `this` from the enclosing lexical scope.
- In this case, the enclosing scope is the global or module scope, where `this.name` is likely `undefined`.
- Therefore, `console.log(this.name)` inside the arrow function prints `undefined`.

---

**💡 Explanation**:

- Unlike regular functions, arrow functions do not bind their own `this`.
- When you call `obj.greet()`, `this` inside `greet` does NOT refer to `obj`.
- Instead, it refers to the outer lexical context, which usually does not have a `name` property.
- To fix this and print `"John"`, define `greet` as a regular function:

```js
greet() {
  console.log(this.name);
}
```

- Then `this` will correctly refer to `obj`, and `obj.greet()` will print `"John"`.

---

This behavior is a common pitfall in JavaScript when using arrow functions as object methods. Understanding the difference in `this` binding between arrow functions and regular functions is crucial for React and frontend development.

💬 **Question**: Why does an arrow function used as an object method print `undefined` when accessing `this.name`?

---

⭐️ **Answer**: The arrow function does not have its own `this` binding. Instead, it inherits `this` from the surrounding lexical scope, which is usually the global or module scope where `this.name` is undefined. So when you call `obj.greet()` and `greet` is an arrow function, `this.name` inside it does not refer to the `obj`'s `name` property but to the outer scope’s `this`, resulting in `undefined`.

---

**Detailed Explanation**:

- In JavaScript, regular functions have their own `this` context, which depends on how the function is called.
- Arrow functions, however, do not have their own `this`. They capture `this` from the lexical scope where they are defined.
- When you define an arrow function as a method inside an object, `this` inside that arrow function does not point to the object.
- Instead, it points to the outer scope’s `this` (often the global object or `undefined` in strict mode).
- Therefore, `console.log(this.name)` inside an arrow function method will print `undefined` if `name` is not defined in the outer scope.
- To access the object’s properties correctly, define the method as a regular function:

```js
const obj = {
  name: "John",
  greet() {
    console.log(this.name); // "John"
  }
};
```

- This way, `this` inside `greet` correctly refers to `obj`.

- Common operations include traversal, insertion at the beginning/end/middle, deletion, and searching.

💬 **Question**: Can you write a program to reverse a linked list?

---

⭐️ **Answer**: Yes, I can write a program to reverse a singly linked list. The idea is to iterate through the list and reverse the direction of the `next` pointers so that each node points to its previous node instead of the next one. At the end, the last node becomes the new head.

---

**🔑 Key Steps**:
- Initialize three pointers: `prev` as `null`, `current` as the head of the list, and `next` as `null`.
- Iterate while `current` is not `null`:
  - Store `current.next` in `next`.
  - Change `current.next` to point to `prev`.
  - Move `prev` to `current`.
  - Move `current` to `next`.
- After the loop, `prev` will be the new head of the reversed list.

---

**💻 Code** (JavaScript/TypeScript style for clarity):

```typescript
// Definition for singly-linked list node
class ListNode {
  value: number;
  next: ListNode | null;
  constructor(value: number) {
    this.value = value;
    this.next = null;
  }
}

function reverseLinkedList(head: ListNode | null): ListNode | null {
  let prev: ListNode | null = null;
  let current = head;
  let next: ListNode | null = null;

  while (current !== null) {
    next = current.next;     // Store next node
    current.next = prev;     // Reverse current node's pointer
    prev = current;          // Move prev forward
    current = next;          // Move current forward
  }

  return prev; // New head of the reversed list
}
```

---

**💡 Explanation**:
- Time complexity is O(n), where n is the number of nodes, since we traverse the list once.
- Space complexity is O(1) as we only use a few pointers.
- This approach works in-place without extra data structures.
- After reversal, the original tail becomes the new head, and all links are reversed.

- For each `i`, use two pointers `left` and `right` to find pairs where `nums[i] + nums[left] + nums[right] == 0`.

function threeSum(nums) {
  nums.sort((a, b) => a - b); // Sort the array
  const result = [];

  for (let i = 0; i < nums.length - 2; i++) {
    // Skip duplicate values for i
    if (i > 0 && nums[i] === nums[i - 1]) continue;

    let left = i + 1;
    let right = nums.length - 1;

    while (left < right) {
      const sum = nums[i] + nums[left] + nums[right];

      if (sum === 0) {
        result.push([nums[i], nums[left], nums[right]]);

        // Skip duplicates for left and right
        while (left < right && nums[left] === nums[left + 1]) left++;
        while (left < right && nums[right] === nums[right - 1]) right--;

        left++;
        right--;
      } else if (sum < 0) {
        left++; // Need a larger sum
      } else {
        right--; // Need a smaller sum
      }
    }
  }

  return result;
}

💬 **Question**: How to optimize the given triple nested loop JavaScript function that finds unique triplets summing to zero, which currently results in a "CPU time limit exceeded" error.

---

⭐️ **Answer**: The current approach uses three nested loops (O(n³) time complexity), which is inefficient for larger inputs and causes the time limit exceeded error. To optimize:

- Sort the input array first.
- Use a two-pointer technique inside a single loop to reduce complexity to O(n²).
- Skip duplicates efficiently to avoid repeated triplets.
- This approach is a classic solution for the "3Sum" problem.

**🔑 Key Steps**:
- Sort the array.
- Iterate through the array with index `i`.
- For each `i`, use two pointers `left` and `right` to find pairs such that `nums[i] + nums[left] + nums[right] === 0`.
- Move pointers inward based on sum comparison.
- Skip duplicates for `i`, `left`, and `right`.
- Collect unique triplets in the result array.

**💻 Code**:
```javascript
function threeSum(nums) {
  nums.sort((a, b) => a - b); // Sort the array
  const result = [];

  for (let i = 0; i < nums.length - 2; i++) {
    // Skip duplicate values for i
    if (i > 0 && nums[i] === nums[i - 1]) continue;

    let left = i + 1;
    let right = nums.length - 1;

    while (left < right) {
      const sum = nums[i] + nums[left] + nums[right];

      if (sum === 0) {
        result.push([nums[i], nums[left], nums[right]]);

        // Skip duplicates for left pointer
        while (left < right && nums[left] === nums[left + 1]) left++;
        // Skip duplicates for right pointer
        while (left < right && nums[right] === nums[right - 1]) right--;

        left++;
        right--;
      } else if (sum < 0) {
        left++; // Need a larger sum
      } else {
        right--; // Need a smaller sum
      }
    }
  }

  return result;
}

// Example usage:
const input = [-1, 0, 1, 2, -1, -4];
console.log(threeSum(input));
```

**💡 Explanation**:
- Sorting helps to efficiently skip duplicates and use two pointers.
- The two-pointer approach reduces the complexity from O(n³) to O(n²).
- This method avoids the time limit exceeded error by eliminating unnecessary iterations.
- It returns all unique triplets that sum to zero without duplicates.
- The space complexity is O(n) for the output and sorting overhead.

This optimized solution is widely accepted for the 3Sum problem and will run efficiently in your environment without timing out.
