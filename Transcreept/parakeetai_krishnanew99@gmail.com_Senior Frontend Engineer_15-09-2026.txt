⭐️ **Answer**: I can solve both parts efficiently using a two-pointer approach. For the first part, we normalize the string by filtering out non-alphanumeric characters and converting it to lowercase, then check from both ends inward. For the second part, when a mismatch is found between the left and right pointers, we can test by skipping either the character at the left or the character at the right pointer.

**🔑 Key Steps**:
- **Part 1 (Palindrome Check)**: Clean the string using a regular expression to keep only alphanumeric characters, convert to lowercase, and use two pointers (`left` and `right`) moving toward the center.
- **Part 2 (Valid Palindrome II)**: Use a helper function with two pointers. When `s[left] !== s[right]`, check if the substring formed by removing either `s[left]` or `s[right]` is a palindrome.

**💻 Code**:
```typescript
// Part 1: Check if a string is a valid palindrome
function isPalindrome(s: string): boolean {
  // Normalize: remove non-alphanumeric and convert to lowercase
  const cleanStr = s.toLowerCase().replace(/[^a-z0-9]/g, '');
  
  let left = 0;
  let right = cleanStr.length - 1;
  
  while (left < right) {
    if (cleanStr[left] !== cleanStr[right]) {
      return false;
    }
    left++;
    right--;
  }
  
  return true;
}

// Part 2: Check if string can be a palindrome by removing at most one character
function validPalindrome(s: string): boolean {
  // Helper to check if a substring is a palindrome between given indices
  const checkPalindrome = (str: string, low: number, high: number): boolean => {
    while (low < high) {
      if (str[low] !== str[high]) return false;
      low++;
      high--;
    }
    return true;
  };

  let left = 0;
  let right = s.length - 1;

  while (left < right) {
    if (s[left] !== s[right]) {
      // Try skipping either the left character or the right character
      return checkPalindrome(s, left + 1, right) || checkPalindrome(s, left, right - 1);
    }
    left++;
    right--;
  }

  return true;
}
```

**💡 Explanation**:
- **Time Complexity**: $O(n)$ for both functions, where $n$ is the length of the string, as we iterate through the characters at most once (or twice in the worst-case mismatch for part 2).
- **Space Complexity**: $O(n)$ for Part 1 due to string normalization and regex allocation, and $O(1)$ auxiliary space for Part 2 since we operate directly on indices without extra data structures.
